# Kubernauts Technical SEO v1.0 — release checklist

The relaunch is **not** approved for indexing by default. `SITE_INDEXABLE=true` is a deliberate build-time release flag, not an automatic feature of merging to `main`.

## Implemented
- Shared canonical, description, Open Graph and Twitter card tags
- Explicit DE/EN homepage alternates, plus correct reciprocal legal page language links
- Organization and WebSite JSON-LD on homepages
- Static `robots.txt` and `sitemap.xml` generated by Astro endpoints
- Preview indexing guard and automated build assertions
- Legal/privacy and brand comparison pages remain noindex even in release mode pending legal review
- Sitemap initially contains only DE and EN homepages after explicit release approval

## Before domain switch (blocking)
1. Confirm legal and privacy pages and authorize publication; remove preview-specific wording.
2. Complete approved service landing pages and a URL-by-URL keep/redirect/410 table. Preserve valuable legacy URLs including active Google Ads landing pages.
3. Decide how old HTML/JSP URLs are actually handled: GitHub Pages cannot return arbitrary server-side 301 rules.
4. Set final navigation, content, structured data and language pairs for every additional page.
5. Check 404 handling, canonical host and WWW redirects, HTTPS, ads landing-page final URLs, links and cookie tracking consent.
6. Run `npm run build` and `npm run verify:seo` on preview, then do a **separate release-mode build** using `SITE_INDEXABLE=true npm run build` and `SITE_INDEXABLE=true npm run verify:seo` in a controlled environment.
7. Run browser/mobile/Lighthouse QA and crawl the generated site; only then approve deploying the release artifact.
8. Verify Google Search Console domain ownership, submit the live sitemap and monitor indexing and rankings.

Do not treat a successful preview build as go-live approval. This is not a live SEO crawl or a guarantee of indexability.
